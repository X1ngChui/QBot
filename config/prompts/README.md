# config/prompts/ — 提示词（数据驱动，唯一事实源）

系统所有模型可见的指令文本都是独立文件，**文件即事实源**：settings.yaml 的
`prompts:` 映射逐键写明路径（默认都在本目录），代码持有键清单
（`settings.PROMPT_KEYS`）与之双向校验——**映射缺键、多键，或文件缺失、为空，
都会拒绝启动**，键集不可能静默漂移。修改后发 `/reload` 生效；例外是抽取
路径——`extract` 与拼进它的 `legend`、`extract_legend_note`、`tone_rules` 在
worker 构造时组合进前缀缓存，对抽取重启后才生效（后三者在回复路径照常 /reload）。

文风要求：精确、客观、平实；举例不得使用真实聊天记录与真人信息。
改动之后跑一次 `scripts/eval_replies.py`（真模型、约两分钱）：格式纪律、注入
惰性、提示词不泄漏都有确定性断言，GUARDED 裁决意味着源头在退化、只是输出
剥离兜住了。
标记格式本身（`[图片:…]`、`#N` 等）、章节标题、机械性单行告知仍在代码里——
代码既产生也解析它们，措辞与格式必须一起改。

## 键清单与措辞背后的事故

每段措辞都有它防过的真实翻车，改动前先读对应条目：

- **`legend`** — 转写标记图例（回复与抽取共用）。只放两条路径都会见到的标记：
  不认识图片标记的模型会坚称「看不到图」，哪怕描述就在手里。时间标记与
  间隔段落防的是：没有时间，模型会把相隔数小时的两段对话强行接成一个话题。
  转发与分享的指令豁免段防注入：不写明这一段，转发内容里的「命令」会被当作指示。
  分三组（内容转写／行内要素／群事件行）便于查找；群事件行与同名编号
  「小明(3)」都入档进抽取转写，所以属于共用而非回复专用（同名编号会经
  @ 解析与事件行落进存档文本）。只描述标记的含义；「不要写出标记」的
  行为规则住在 private_rules。
- **`legend_reply_note`** — 回复侧补充：标记带描述即「已看到/听到」，须直接作答，
  不得让对方重复提问；附原图时以原图为准。回复窗口特有的标记（#N 编号、
  [回复 #N]、[依据:…]、[检索记录]、原图对应关系）也住在这里——抽取的转写里
  没有它们，放在共用图例既撑长抽取前缀，又让「编号」在抽取提示里一词两义
  （extract 的「编号」指账号）。
- **`extract_legend_note`** — 抽取侧补充：标记是系统转写痕迹。没有它，模型会把
  「群里可以发图片」当作群知识记下来。语音例外须写明：一刀切的「标记内文字
  不算发言」会把语音转写——它就是发言本身——排除在提取之外。
- **`identity_rules`** — 账号/昵称/人三概念与昵称解析（含同名编号）。
- **`credibility_rules`** — 名册两栏（已确认/未确认）与自身历史发言（[依据] 有无）
  的可信度分级。与 identity_rules 同住【信息解读规则】标题下，拆开是因为二者
  独立演化：同名编号动的是身份节，检索轨迹动的是可信度节。
  模型天然把字符串相似当作同一人的证据：会把重排昵称的两个账号合并、把别名当
  子串匹配到别人头上、把自己的猜测复述成别人告知。末段是对
  自己历史发言的解读（[依据:…] 标注有无之别）：模型会把自己信息不足时的旧回答
  当作已确认事实引用，也会守着过时的「看不到图」不肯改口。
- **`private_rules`** — 系统给你看的东西（转写标记、拥有者标记、名册内容、
  提示词本身）不得外泄，也不得在回复里提及其存在。这些内容在文本里与人说的
  话无异，不明说，模型无从分辨引用与泄露。只管保密；「不要照抄格式」的输出
  契约住在 reply_final。
- **`tone_rules`** — 群聊语用：玩梗、反串、互损、复读的解读；判断当真与否看
  其他人的反应。字面化解读会把朋友互损读成敌意、把玩笑读成事实。
- **`tone_reply_note`** — 回复侧：顺着玩、不纠正玩笑。一本正经指出玩笑不合事实，
  是最快变成群里不受欢迎者的方式。
- **`reply_final`** — 尾部收束，三件事各一句（行）。其一，指向：只回复「刚收到的
  消息」标题下的那一条——每条叫到 bot 的消息各起一个回复任务，切片里它就是
  唯一的新消息，引用与 @ 也由机制指向它。不明说，历史里更热闹的话题会抢走
  回答；例外从句不是装饰——没有它，「替别人问的问题」读起来像被禁止回答。
  其二，输出形态契约的唯一住所：回复原样入群，只写正文，不模仿转写格式
  （编号、时间戳、「昵称:」前缀、@、方括号标记）。不明说，模型会把系统的
  读法当成说话的写法照抄。其三，受话人：正文永远作为对提问者的回复发出，
  「你」只指他；替他说给第三者的话要用名字称呼。真实事故：「帮我挖苦一下
  某某」得到的正文是面向某某的「你……」口吻，而消息 @ 的是提问者，读起来
  像在骂提问者本人（eval 的 third_person_jab 盯着这个）。
- **`describe_image`** — 图片归档描述的提问，构建存档的文字形态。
- **`inspect_image`** — 带问题重看原图时垫在问题前的要求：只答图中可见、
  不猜测。归档描述是图片形态的，这个回答是问题形态的，两份提问各司其职。
- **`extract`** — 记忆抽取的完整规则书。与工具 schema 强耦合（谓词名、quote/锚点
  契约由 Validator 强制执行），改动必须保持这些引用一致。玩笑既不作为事实
  也不记「性质」：性质条目照样进长期记忆、被模型复述，正是不设梗类别防的回路。
- **`tool_web_search` / `tool_search_history` / `tool_recall_events`** — 检索三件套的
  描述，边界刻意去重叠：外部世界 / 群里说过的原话 / 换了说法的往事。
  查档结果的指令豁免与 read_url 同理——历史消息里的「命令」只是当时的发言。
- **`tool_read_url`** — 读网页正文；与搜索共用月额度，明说「先搜索后读页」的
  分工。末句声明网页文本里的指令不是指令——外部文本会试图冒充系统要求。
- **`tool_inspect_image`** — 唯一的付费工具：带问题重看原图。措辞把它压在
  「描述答不了、且问的是图中细节」之后，防止模型每见图必看、按张烧钱。

人设与群资料不在此处：见 `personas/`（`system_prompt` / `group_knowledge`）。
