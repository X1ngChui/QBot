# QQ 群聊 AI 机器人 · 设计文档

> Python · 个人单机 · 2026-08-28 · v6（描述已实现系统）
> English version: [design-en.md](design-en.md). 中文版为权威版本；两份不一致时以中文版为准。

一个参与 QQ 群聊的 AI bot：被 @ 或叫到名字必答，其余时候沉默；记得住群友和往事；能看懂图片、听懂语音（只收不发）。v5 是实现前的规格，本版描述 2026-08 大重构后的实际系统。

代码注释以「design doc section N」「design goal N」「(DN)」引用设计文档；其中两位数的大节号（46、52、63 等）沿用 v5 规格的编号，作为稳定锚点保留，不对应本版的章节。改动任何编号前先全库检索这些引用。

## 设计目标

代码注释按编号引用，编号不可重排：

1. **经济性**：前缀缓存命中价是未命中的约 1/30，一切排布（提示词分层、窗口成块淘汰、批量抽取）都围绕命中率；一次调用读一段对话，而不是一条一调。
2. **实测优先**：模型、维度、阈值的取舍以实测数据为准，不以直觉为准（embedding 维度、RAG 方案、缓存命中率都实测过再定）。
3. **能不做的不做**：一个机制的维护成本超过它省下的东西，它就是负债（见附录 D8 三问）。
4. **群隔离**：携带 group_id 的表以 group_id 为索引首列，不存在跨群检索路径；唯一例外是拥有者手工建立的全局别名。
5. **钱是唯一限制**：免费的事情不限次数；付费动作对钱负责，不设次数配额这种会随价格漂移的代理指标。
6. **超限即止付**：约束目标是消耗有界，不是已花的钱作废。日预算在花钱之前检查，触顶直接不回复；回复进行中的限额（单次回复预算、搜索月额度）触顶则停止一切还会花钱的动作，追加一轮无工具收尾调用、用已取得的材料作答——超射恰好一轮，依然有界。
7. **结构化输出一律 function call**：模型往系统里写东西（记忆候选、别名）只经工具调用 schema，不解析自由文本 JSON。
8. **文本是归档形态**：模型看原图，存档存文字描述——检索、抽取、重启重建都吃文本。

## 决策总表

| 决策 | 一句话理由 |
|---|---|
| 协议端 NapCat（OneBot v11，反向 WS） | 唯一活跃的选择；接受第三方协议端的封号风险 |
| 框架 NoneBot2 | Python 生态最成熟，插件体系不碍事 |
| 文本与视觉同为 `deepseek-flash`（V4.1-Flash，多模态，2026-09-10 起） | 回复模型自己能看图，于是原图直接进 prompt，代读的 `inspect_image` 删除；从此只用多模态模型，「文本模型读不读得了图」这个开关也一并删除；描述仍照写不误，因为检索、抽取、重启重建都只吃文本，且描述在到达时就写、包括 bot 从不发言的群 |
| 模型配置按用途组织而不只按能力：`llm.text` 是回复路径，`llm.text.extract` 是同一账号的另一种读法，`llm.vision` 负责描述。每种用途各有自己的模型、`reasoning_effort`（off/low/high/max）与超时 | 思考按输出计费，而反直觉规则与思考共存亡（off 档实测必丢别名再确认，low 是地板）；各用途当前均为 low。端点、凭证、并发与重试保持共享——它们描述的是账号而非任务，端点抄成两份就是其中一份迟早过期 |
| ASR：进程内 sherpa-onnx（SenseVoice int8，CPU）；Embedding：百炼 `text-embedding-v4`（2048 维，API） | 中文口语实测 SenseVoice 优于 Whisper 系，非自回归小模型 CPU 秒内转完，零费率；Embedding 维持 API（D 5.2） |
| 搜索：Tavily 免费档（1000 次/月），独立调用 (D5) | 零边际成本；不用模型内置搜索（双重计费且破坏前缀缓存） |
| 存储：Postgres 17 + pgvector，本地磁盘 | 二十张表一个向量存储；NFS 的 fsync 不可靠，NAS 只做备份 |
| 触发 = @/昵称/引用 bot 发言必答，其余沉默 | 仲裁器、兴趣向量、自适应强度全部删除（附录 D1/D7）；一条规则，无旋钮 |
| 记忆结构化：实体/别名/事实/事件四层，置信度实证驱动 | Wilson 下界 + 渠道融合 + 谓词分类衰减；v5 的散文画像方案已废弃（附录 D2） |
| 只发文字 | 图片/语音只接收理解；输出层只有 `clean_reply()` |
| 无 fallback、无自动降级 (D6) | 故障就停；被点名而沉默的日志有专门条目，静默失败可诊断 |
| 凭据走 `.env` | compose `${VAR:?}` 注入，缺项在 `up` 时报错而不是几小时后 401 |
| 运行时全国内直连；唯一例外是搜索客户端走本机 HTTP 代理 | 代理只挂在免费且可失败的路径上，模型热路径不加单点 |

## 1. 风险前提

第三方协议端违反腾讯用户协议，可能封号。已接受，代码层面强制执行：

- 小号 + 养号后再上；固定 IP。
- 无回复限速：每条被叫到的消息恰好一次回复尝试，节奏由预算与 provider 层并发信号量（`max_concurrency: 3`）自然约束。

## 2. 架构

```
QQ ←→ napcat 容器 ←OneBot v11 反向WS→ bot 容器 ←asyncpg→ postgres+pgvector 容器
```

### 消息管线

```
消息到达
 ↓ 去重
 ↓ 写 raw_event                      异步，无条件留档；重放不落第二次
 ↓ 免费解析 + 图片处理               @解析、引用、转发；图片当场下载→传 Files API→异步描述回填
 ↓ 触发判定（§4）──否──→ 结束        每条消息独立判定；叫到的消息当场截取上下文切片，
                                     发起一个并发回复任务（引用、@、记账都归本条的发送者）
 ↓ 任务内：日预算闸 → 屏蔽（只扣回复不扣接收）→ 用户协议闸
 ↓ 检索：名册/画像 → 群知识（事件记忆不推送——模型用 recall_events 自己查）
 ↓ Prompt 组装（缓存友好排序 §6.2，纯文本，原图按需 open_image 取回）
 ↓ 金钱边界的工具循环（§2 引擎）
 ↓ strip_markdown → 发送（引用触发消息并 @ 其发送者）→ 自己的回复也入档
```

### 会话引擎（Agent Loop）

无轮数配额、无工具配额，边界是钱：

```
with BUDGET.scope(per_reply_cny):
    循环（失控保险丝 20 轮，只防计费为零的后端）:
        调模型（思考档位按配置，恒定提供全部工具）
        无工具调用 → 返回正文
        预算闸：本次回复已花到上限 → 转入无工具收尾轮，用已有材料作答。首轮永远运行
        执行工具（重复同参调用不再执行，文字告知）；搜索月额度触顶 → 未执行的调用以
            占位结果补齐，同样转入收尾轮
        结果以 tool 消息追加在缓存边界之后
```

五个工具：`web_search`（Tavily，经代理）、`search_history`（本群 L0 存档布尔检索：Lucene 语法经 luqum 解析——空格=AND、OR、`-`排除、括号、引号短语，仅接受布尔子集、其余语法以文字拒绝；AST 递归编译为参数化 ILIKE，成员词只进参数不进 SQL 文本；可按发言人与天数过滤；命中连同前后各 `retrieval.history_context` 行一起返回——聊天是碎片化的，命中行常常只是对上一行的应答——相邻窗口并块、块间省略号分隔，过滤只选命中、上下文照实呈现；命中消息整条返回、结果也不设字数配额——长消息只占全库 1%，却承载了最值得检索的内容，按固定宽度切会精准砍掉它们；结果的大小已由命中数×上下文行数×单条消息上限三重决定，再往上是钱，字数配额只会是同一件事上更钝的第二道约束）、`recall_events`（本群事件向量召回；召回的事件带前后各 `retrieval.episode_context` 块相邻事件——事件是整段对话的摘要，来龙去脉就在相邻块里——同样并窗、省略号分段，无日期者单独成段）、`read_url`（读网页正文，与搜索共用月额度）、`open_image`（按编号取回图片原图，一次最多 `retrieval.open_image_max` 张，作为 file block 直接交给模型看）。五个工具**全部免费**——一次 SQL、一次 HTTP 取回、一次文件上传；边界仍然是钱，因为承载它们的每一轮本身是付费模型调用。分工写在工具描述里且刻意去重叠。

### 并发

全局 `max_concurrency: 3` 信号量在 provider 层；每条被叫到的消息一个独立回复任务，任务间并发（各带到达时截取的上下文切片，预算归因走 contextvar 任务隔离）；后台任务（抽取、embedding）走 DB 任务队列（FOR UPDATE SKIP LOCKED + 租约 + 待办去重索引）。

### 输出

只有 `clean_reply`（剥 QQ 渲染不了的 Markdown——加粗、标题、代码块、分割线、链接语法——但保留纯文本本来就承载得了的东西：「- 」分点保留，`*`/`+` 归一成「- 」，于是真的是清单的回答读起来就是清单；剥全部系统标注——编号、时间戳、⟦依据⟧、⟦检索记录⟧、⟦回复 #N⟧、名字后缀标注，及新旧两代括号形态——剥文本形态的工具调用残片，末级把任何残余保留括号替换为方括号）；长度截断在发送前由 engine 施加。没有别的出口。

## 3. 功能范围

做：被点名必答；群聊记忆（人、事、群知识）；图片理解（原图直读 + 归档描述）；语音转写；联网搜索；存档检索；指令面（只认 bot 拥有者、不认群管理，两类例外：/who /note /alias /forget 对普通成员开放「仅限自己」，成员手工录入与拥有者同效，/agree /terms 天然属于本人；/card /stats /top /groupstats 只读、成员可整体查看。/help 列表按身份过滤，越权一律沉默）；用户协议门槛（未 /agree 的成员叫到 bot 时得到一句指引而非回复，按冷却限频，指引以关于该成员的群事件标注入档、不记为 bot 发言——模型会复述它读到的「自己说过的话」：/terms 展示协议全文、/agree 表示同意，二者也是同意前仅有的可用指令；同意按（群，账号）+ 协议版本记录、各群分别同意、版本升级需重新同意；消息照常接收存档，拥有者豁免；版本号与正文文件路径是强制配置（settings.yaml 的 agreement 块，正文随配置一并加载、缺文件拒绝启动，/reload 同步生效）。屏蔽仅意味着不回复：消息照常接收、存档、进入记忆，保持上下文连贯；可带时长（30m/12h/3d），到期在其下一次叫到 bot 时惰性解除，不设调度器。群事件（入群、退群/被踢、撤回、禁言、戳一戳）转写为一行方括号文本进入窗口与存档，绝不触发回复。
不做：主动插话（仲裁器已删）；发图发语音；跨群记忆共享；多账号。

## 4. 触发

一条规则：@、昵称词命中、或引用了 bot 仍在窗口内的发言（即使手动删掉了回复自带的 @）→ 必答；否则沉默。昵称用 jieba 分词按**词**匹配而非子串（「小夜曲」不触发「小夜」）。静音（/mute）高于被点名。

v5 的概率闸门、Flash 仲裁、自适应 p_max 整层删除：bot 只在被叫时说话后，「要不要主动插话」这个判断不复存在（附录 D1、D7）。

## 5. 模型、外部服务与预算

### 5.1 服务清单

| 能力 | 后端 | 模型/端点 | 凭据 |
|---|---|---|---|
| text | deepseek | `deepseek-flash`（多模态，low 思考；`llm.text.extract` 可单独指定抽取的模型、思考档与超时——模型当前空置，即跟随回复模型） | `TEXT_API_KEY` |
| vision（专职描述） | deepseek | `deepseek-flash`（与回复同一个模型，但仍是独立能力：描述在到达时给每张图写，包括 bot 不回复的群） | `TEXT_API_KEY` |
| asr | sherpa（进程内） | SenseVoice int8（sherpa-onnx，CPU；权重在 `models/` 挂载卷，`fetch_asr_model.sh` 一次性下载） | 无——零费率入账，账本照记 |
| embedding | dashscope | `text-embedding-v4`，2048 维 | `MEDIA_API_KEY` |
| search | tavily | `/search`，basic 档 | `SEARCH_API_KEY` |

五个能力五个独立配置块（`llm.<capability>`），各自携带 endpoint/model/凭据名，互不借用——embedding 曾借 vision 的接线，vision 搬家时被静默拖走导致全线沉默（真实事故）。注册表按 `backend` 选实现类；平台怪癖（缓存计量字段、禁思参数）只住在实现类里。

上传图片归 text 能力而非 vision：文件必须存在那个将要读它的账号下，因此 `TextModel.upload` 返回该平台发的句柄，providers 层以上一律只说一种中立块 `{"type": "image", "id": ...}`。发出去时各后端各自翻译（DeepSeek 要平铺的 `file_id`，拒收 OpenAI 文档里的嵌套写法）。prompt 构造侧不认识任何厂商的写法，这正是「换平台只是加一条注册表项，而不是改 `prompt.py`」的前提。

### 5.2 已弃用（避坑）

- 本地 embedding（bge-small + PyTorch/ONNX/NPU 整条线）：实测 API 的 2048 维分离度更好且免维护，权重、HF 镜像、fetch 脚本全部删除。
- 智谱搜索：Tavily 免费后无存在理由。
- 百炼 qwen 视觉渲染：DeepSeek 视觉上线后退役。
- 模型内置搜索 `enable_search`：双重计费 + 插入位置不可控破坏前缀缓存 (D5)。

### 5.3 图片与语音

**图片在到达时处理**（此时 CDN 链接最新鲜）：下载 → 异步用视觉模型写一句描述回填 `plain_text`。描述是归档形态（design goal 8）：检索、抽取、重启重建、以及超出图片上限的那些图，四个消费者都只吃文本，而且描述是**到达时**给每张图写的，包括 bot 从不发言的群——回复模型在那里根本不运行。回复模型自 2026-09-10 起是多模态的；自 2026-09-11 起不再主动附图：所有图片只以带编号的描述行（或无描述的裸标注）出现，模型需要看像素时用 `open_image` 按编号取回，一次最多 `retrieval.open_image_max` 张（默认 6）——DeepSeek Flash 的一轮工具调用足够快，换来的是历史逐字节稳定、缓存不再随附图栏位翻转。取回靠 `image_cache.file_id`（到达时免费上传，`file_uploaded_at` 超过 `llm.vision.file_max_age_days` 视为已过期、重新上传）。转发的聊天记录（协议端随消息内嵌 `content`，嵌套亦内嵌）渲染为承载消息下方的缩进块：首行 `⟦转发的聊天记录 N条⟧`，每条目一行「⟦时间⟧ 昵称: 内容」，嵌套一层多缩两格，受 `prompt.forward_lines/forward_depth/forward_chars` 三重界限、超出以 `⟦其余N条未显示⟧` 收尾；记录里的图片是承载消息自己的引用，随之编号、可 open，但只免费上传、不付费描述。描述调用按图片内容缓存（转发不再付费）、每分钟限速、日预算闸。缓存的描述过 `llm.vision.description_ttl_days`（15 天）失效：模型会越来越强，而厂商可能在同一个模型 id 背后换更好的模型——按模型 id 盖戳看不见这种变化，按时间可以。刷新天然是惰性的，因为只有被再次发出的图才会被查到：没人转发的图无论描述多旧都不会付第二次钱，已经归档的转写行也保留当初的措辞。后端内容过滤拒看的图同样按这个时钟缓存为一个带标记的占位符，换后端之后可以重看——此前那一次拒绝会让 bot 对那张图永久失明。没有附上原图的那些，走回复循环的 `open_image` 工具按编号取回——转写里每张图的标注都带编号（⟦图片3:描述⟧），编号是它在当前这份记录里的序号，随渲染而变，与行号同理。图片引用（`image_refs`）随消息在窗口内保留、重启后从存档 payload 重解析，QQ 的 file id 随时可换新链接。旧的 `inspect_image`（把问题转给另一个模型代看、返回一句话）已删除：模型自己能看之后，这个中间人既多余又更差——它只能回答预设的那一个问题。

**语音与图片同处：到达即转写**（2026-09-07 起）：语音出现频率远低于图片、按秒计费也更便宜，而不转写它就是归纳的盲区——归纳只读文本，回复时才付费意味着没人问过的语音永远不进记忆。到达时经 `get_record` 取 NapCat 转码的 WAV、异步转写回填 `plain_text`；失败保持未决，回复路径的结算兜底重试。「付费动作等回复」的旧纪律就此整体退役（D11 修订）。转写自 2026-09-08 起在进程内完成（`sherpa` 后端：sherpa-onnx + SenseVoice int8，CPU 双线程，一条十秒语音亚秒转完）：零费率入账、无凭据无端点；日预算闸只拦花钱的后端，免费转写直接穿过，每分钟限速保留为 CPU 保护。按秒计费的 API 后端仍在注册表里，一行配置换回。

### 5.4 预算——钱是唯一限制

两级，都在 `core/budget.py`：

- **日预算** `daily_cny_cap: 3.0`：触顶后 bot 停止回答、worker 停止付费工作，直到日期在配置时区滚动。总额从 `cost_ledger` 恢复，重启不清零。
- **单次回复** `per_reply_cny: 0.30`：`with BUDGET.scope(cap)` 圈住工具循环，每个后端把自己算好的开销记账进来。花到上限 → 停止工具、转收尾轮。闸门读的是已花的钱，不预测下一轮：预测需要模型的价格，而费率表不认识的模型会让预测永远失败——工具循环于是在零花费下被摘光，看上去与「模型不肯检索」一模一样。

归因（contextvar，只喂 /top 排行，不改变共享预算）：bot 只被动回复，因此一次回复的全部开销——含其间的语音转写、看图与搜索——都记在发起者（@ 或叫到名字的那条消息的发送者）头上；图片的入档描述记在发图人头上；归纳等共同开销不记名。

超限即止付（design goal 6）：日预算在入口检查、触顶即沉默；回复进行中触顶（单次预算、搜索月额度）不整条作废——未执行的工具调用以占位结果补齐协议，追加一轮无工具收尾调用，模型被告知额度已尽、只依据已有材料作答。搜索月额度（1000 credit）由 ledger 的当月 calls 计数充当计量表——按厂商的记账单位记（advanced 深度一次记 2，`read_url` 的网页读取同池扣减）；传输故障则是另一回事——以「搜索失败」告知模型继续，故障不是限额。

定价表住在各后端类里，含 DeepSeek 峰谷（工作日 9-12/14-18 北京时间 ×2）与 2026-08-17 调价的双时代表；未知模型一律按最贵档计费并告警一次，宁可早触闸。记账按实际服务的模型，而非请求时写的那个——两者未必相同。全部数字与官方页核对过（最近 2026-09-09，无变化、无预告调价）。

## 6. 记忆与上下文

### 6.1 存储

二十张表，分层（L2 刻意缺席：@ 和引用由平台明示账号，无判断可记）：

- **L0 `raw_event`**：只追加的原始档；`payload` 是平台原文永不修改，`plain_text` 是可回填的衍生读法（图片描述、语音转写落在这）。
- **L1 `entity` / `identity_account` / `alias`(+evidence)**：人、账号、名字分开。人级操作只有两个原语：写侧**展开**（`accounts_of_person`——/block 对人生效），读侧**按 entity 聚合**（join `identity_account`、group by entity_id——/top 排行按人计）。merge 物理重指账号行，所以读侧聚合对事后合并天然正确；新的人级功能二选一，不再各自发明。账号是强身份；名字带作用域、证据链与状态。别名置信度=渠道内取最大、跨渠道 noisy-OR 融合；平台名首日只算候选（防改名逗弄），手工证据一票定论，退役的名字钉死不复活。
- **L3 `memory_fact`(+evidence) / `memory_candidate`**：时序语义事实，29 个谓词，多值谓词以 `object_key` 区分；「一个主语一个谓词只有一条现行事实」由部分唯一索引在数据库层保证。置信度用 Wilson 下界从**不同来源事件数**挣得（1 条≈0.27，3 条≈0.53，8 条≈0.75），重复确认原地累积证据而不是新增行。衰减按谓词分类（稳定 90 天/快变 14 天/默认 30 天），证据越多半衰期越长。一个谓词就是 `config/predicates.yaml` 里的一条：含义、单值/多值、衰减档、记忆类型、名册里的中文读法、以及给抽取模型看的判定规则全在这一条里，所以加谓词是改配置，且不会只改一半。提示词里必须留有渲染谓词表的位置，否则配置加载失败。
- **L4 `episode`(+participant/event)**：事件摘要，向量检索。
- **L6 `embedding_index` / `memory_job`**：向量投影与被投影物解耦；任务队列。

会话窗口（即时上下文）在内存 deque 里，重启后从 L0 重建——bot 不会带着失忆重新加入三十秒前还在聊的对话。工具循环的检索轨迹（每次回答查过什么、结果摘要）住在独立的 `reply_trace` 表——单一事实源，deque 只装对话。组装提示词时按窗口内的回复查表，把每条 `⟦检索记录⟧` 插在它喂过的那次回答之前：行内容来自不可变的表行、位置由回复决定，逐轮逐字节稳定；回复滑出窗口，它的轨迹自然不再被查，淘汰无需任何簿记，重启也无需特殊处理。它是 bot 的工作笔记而非群聊记忆，不进 L0，检索与抽取都看不见它；与 L0 同样永不删除（拥有者的取舍：行很小，磁盘不是约束）。已读水位线（`group_state.last_extract_at`）记录抽取**实际读到哪**，只进不退；唯一特许例外是 /relearn 显式重置。

### 6.2 检索与 Prompt 组装

排序即成本纪律（design goal 1），最稳定的在最前：

```
全局常量（图例、解读规则、私有规则、语用）→ 人设 → 群知识 → 名册与画像（按账号序，稳定）
→ 会话历史（只追加；3 块 × 每块 30 条 = 90 条封顶，超限一次砍一块）
→ [缓存边界] → 时钟 → 工具结果 → 当前消息
```

没有任何 token 预算：各块完整渲染，各自的作者（拥有者、带长度纪律的生成提示词）负责克制；仅剩的两个数字是窗口条数与淘汰块长，为上下文有限与缓存服务，与钱无关。prompt 里没有任何原图：图片只以带编号的描述行出现，模型用 open_image 按编号取回（一次可多张），于是每条消息在两轮之间逐字节相同，缓存不会因为一张新图挤掉旧图而翻转。

每行携带自身的发送时刻（`⟦月-日 时:分⟧`，回复历史、抽取转写与 `search_history` 结果共用一种格式）：没有它，模型把 60 条消息读成一段连续对话，会强行把相隔数小时的话题接在一起。时刻在消息到达时定格、永不改写，因此与缓存友好性无冲突——任何相对表述（「5分钟前」）都会每轮作废前缀，绝对时刻一次写死。「当前时间」行在缓存边界之后，供模型对表计算间隔。

**系统标注不可伪造**：全部系统标注只用保留括号 `⟦ ⟧`（U+27E6/U+27E7，`util.sysmark`），而一切不可信字符串——成员文本、昵称、图片/语音描述、转发与卡片内容、网页与搜索摘要——在进入转写前经 `util.defang` 把这对括号替换为普通方括号。于是「⟦⟧ 内才是系统标注」成为模型可机械执行的判据：名字叫「小明（拥有者）」、正文写「[图片:…]」的成员产生的都是普通文本，与语法零碰撞（旧方括号语法只能靠措辞恳求模型别上当）。时间戳、`⟦拥有者⟧`、`⟦同名N⟧`、`⟦回复 #N⟧`、`⟦依据:…⟧`、`⟦检索记录⟧`、媒体与群事件标注全数在此语法内；转写行以时间头开头，其余行是上一条的换行，多行消息伪造不了行首。`clean_reply` 的末级兜底把回复里任何残余保留括号替换掉，标注永不出群；
拉式检索补推式窗口：窗口外的东西靠 `search_history` / `recall_events` 按需取。

模型区分人的唯一手段是名字，而两个成员共用一个群名片是平常事：成员名单刷新时按当前名片做同名检测，撞名者一律渲染为「名字⟦同名N⟧」，N 是该账号在本群的永久序号（`member_seq` 表，只增不改不复用——旧转写里的编号永远指向同一个人）。改名会产生新的重名、也会消解旧的重名，随下一次名单刷新自然收敛；名单刷新是「当前名字」的唯一咽喉（重标窗口、名册、@ 解析、群事件行都从它取名）；名册对回退到存档名的行（已退群的同名者）另留一道兜底编号。`search_history` 的发言人参数接受带标注形式（旧式「名字(N)」也接受——旧存档文本里它仍会出现），按序号锁账号而不按名字匹配。归纳路径与此无关：抽取转写本就按批内账号编号指认，写入只收编号。

### 6.3 写入：抽取 → 验证 → 合并

抽取集中在每天一个事件点（`nightly_cron` 流水线首段，02:30——整天记录已齐，谷价，无人等待）：从水位线起最旧优先、按 ≤120 条一块排干当天全部未读，块尾对齐 ≥30 分钟的对话间隙——批次边界落在对话结束处，事件不再被拦腰切开；不足 20 条的零头留给明天。没有实时触发，也没有闲时冲刷：记忆最多滞后一天，而回复的即时上下文本来就是窗口。每块一次调用：文本模型按抽取自己的思考档位读，known-facts 随行防止重复学习，「你的名字」行给出 bot 自己的触发昵称——群友直呼其名的话不再被安到旁人头上（生产实测：bot 的名字曾被记成另一个机器人账号的已确认别名）。理解层与回复路径共享：判读玩笑的【群聊语用】（tone_rules）两路径同一份、各接自己的后果注（回复：怎么接话；抽取：不产生候选），拥有者手写的群背景（personas 的 group_knowledge）也注入 known 块头部——读懂对话所需的材料不再是回复路径的独享，各群由此组装各自的提取输入。bot 自己的发言（含指令答复）也进转写，标注为「名字⟦你⟧」、无编号、不入名册：抽取读到对话的双方，但自有发言只供理解、机械上不可作证据（own 行不参与 quote 匹配，引用它的候选过不了校验）——理解与防自我回路兼得。产出走 function call（design goal 7）；候选记录批锚点与批长度，重放精确到行。/relearn 把水位线回拨恰好一窗并强制越过最小批门槛。**纯代码 Validator** 把关：逐字引文必须在单条消息内命中、批锚点可复现，不合格的候选整条拒绝。Consolidator 落库：同族事实取最新、旧值盖 `valid_to` 不删除、Wilson 重算置信度、传入置信度只作下限。模型提议，代码裁决。

### 6.4 归档与遗忘

L0 永不删除。事实按谓词类衰减（夜间流水线在抽取排空之后的一段），衰过阈值改 superseded 不物理删。episode 只追加。`pg_dump` 是流水线再下一段，滚动 14 份。

## 7. 部署

### 7.1 三容器

compose 三服务：postgres（pgvector 镜像，bind mount `data/pg`）、napcat（`NAPCAT_ACCOUNT` 快速登录，重启免扫码）、bot。凭据全部来自 `.env`，`${VAR:?}` 缺项即拒起。三容器 json-file 日志 20m×3 封顶；应用日志 RotatingFileHandler 5MB×3。

**部署只用 `scripts/deploy.sh`**：整目录替换 + `up -d --build` + 容器内内容指纹核对（`_fingerprint.py`），不一致非零退出。`docker compose restart` 不重建镜像会静默跑旧代码——这是真实吃过两次的亏。SSH 走 `~/.ssh/config` 的 `server` 别名。

### 7.2 本机负载

生成全在云端，本机只有 asyncpg 和 HTTP 客户端；postgres 做了 SSD 参数（`checkpoint_completion_target` 平滑写峰）。无绑核、无监控依赖 (D6)。

### 7.3 网络

运行时国内直连。仅有的两个例外：搜索客户端指向本机 HTTP 代理（`llm.search.proxy`，容器内 `172.17.0.1:7890`）——挂在免费且允许失败的路径上；构建期 `BUILD_PROXY` 只影响镜像构建。

### 7.4 定时任务（APScheduler）

| cron | 任务 |
|---|---|
| `nightly_cron` 02:30 | 夜间流水线，按依赖顺序串行：记忆抽取（唯一事件点，排干全部未读）→ 记忆衰减 → pg_dump（保留 14 份）→ NapCat 媒体缓存清理（7 天）。阶段之间等待任务队列排空（各设截止：抽取 3 小时、衰减 30 分钟，超时记错并继续）——衰减不得在某群的抽取重试还挂在队列里时先跑，备份应带上当晚学到的东西，而这两条墙钟都保证不了（抽取经任务队列排干，重试退避最长可达一小时）。接受的代价：流水线中途重启则当晚剩余阶段跳过——衰减次晚补上，漏掉的备份由日报的备份年龄行报警 |
| `report_cron` 00:00 | 拥有者日报，在账本日界（预算重置的同一午夜）闭账即发：花费明细、分用途缓存命中率（回复/归纳/其他）、搜索月额度、任务队列深度、新群、异常摘要 |
| 常驻 | 任务队列 worker（含租约回收；抽取任务持 30 分钟租约，防部署重叠双跑） |

## 8. 配置

`config/settings.yaml`（全局）+ `config/personas/group_<gid>.yaml`（人格与每群 overrides，只写差异）。纪律：**每个字段都必须有读者、都必须是真选择**——单值旋钮、死机制的开关一律删除（`heavy_when`、token 预算块、`enabled_groups` 都是这么没的）。校验在加载时全量报错（pydantic `extra="forbid"`）。新群零配置：首条消息即服务、默认人格、日报可见。

**提示词是数据**：全部模型可见指令文本以独立文本文件存放，文件即事实源；`settings.yaml` 的 `prompts:` 映射逐键给出路径（相对配置目录解析），代码只持键清单（`settings.PROMPT_KEYS`），映射与清单双向核对，缺键、多键、文件缺失或为空都拒绝启动；`/reload` 生效（抽取提示词构造时组合，重启生效）。各段措辞的事故注释在 `config/prompts/README.md`。标记格式本身、章节标题、机械性单行告知仍是代码——代码既产生也解析它们。

## 9. 存储

本地 SSD；`data/pg` bind mount；备份目录可指 NAS。DB 现约 20MB。2048 维超出 pgvector HNSW 上限是刻意取舍：检索先按群过滤只剩几百行，精确扫描比近似更准且够快（design goal 2 的实测结论）。

## 10. 运维与路线

- 观察面：`/stats`（预算、调用数、搜索月额度、分用途缓存命中率）、`/groupstats`、09:00 日报（含输出剥离计数——每次命中都是一次未遂泄漏，源头纪律退化在报表里可见）。
- 排障：`/debug N` 捕获接下来 N 轮模型调用的完整请求与原始回复到 `logs/debug/`，看模型当时读到了什么而不是事后推断；捕满自动关闭，重启即失效。
- 行为评测：`scripts/eval_replies.py`，拥有者在工作站对真模型手动跑——确定性断言（不复现标记、不以 @ 开头、注入指令不生效、提示词不泄漏）加供人眼看的观察例。裁决分三档：PASS / GUARDED（模型写了、输出剥离剥掉了——源头在退化）/ FAIL。按次付费（单跑约 ¥0.02），刻意不进 CI（design goal 5）；改提示词或换模型前后各跑一次。
- 上线检查表由 `scripts/preflight.py` 机械化执行：对每个能力各打一次真实最小调用，凭据、连通性、模型可用性一次验清。
- 已知弱点（有意接受）：告警只有日报一条通道；bot 容器无 healthcheck（靠 NapCat 重连兜底）；日预算入口检查，并发回复可小幅超射；搜索月额度耗尽后，需要搜索的提问整月只能凭已有材料作答（止付收尾语义的直接后果，拥有者知情选择）。
- 测试：12 套件（`tests/run_all.py`），真 Postgres（qbot-pgtest 容器）；commands.py/tasks.py 因 import 期注册无法被导入，靠 AST 解析守卫（语法 + 属性解析 + 权限闸存在性）兜底。

## 附录：设计决策记录

保留理由备查；标 ~~删除线~~ 的已被后续实践推翻。

**D1 ~~触发强度自适应~~ → 整个主动插话路径删除**：自适应 p_max 省的是手调，但「要不要插话」这个判断本身被「只在被叫时说话」消解。删掉的不是参数是问题。

**D2 ~~记忆不做结构化~~ → 结构化 + 实证置信度**：散文画像曾发生凭空捏造成员的事故，且无法逐条修正。现行方案的置信度可被证据累积、可被命令覆盖、可按类衰减——这些都是散文做不到的。文献依据：Wilson 下界、多渠道 pooling（arXiv 2608.11275）、均匀衰减劣于不衰减（ScrubJay）。

**D3 NPU 不用**：负载画像不匹配（同 v5）。后续本地 embedding 整条线删除，问题不复存在。

**D4 pHash 不做**：文字梗图误判率约 1/3 且错误描述会进记忆放大；md5 免费够用（同 v5）。

**D5 搜索独立接**：模型内置搜索双重计费且插入位置破坏前缀缓存。Tavily 时代依然成立。

**D6 无 fallback / 无自动降级**：故障切换是最少被测试的路径。被点名而沉默是无法与故障区分的最坏失败；日预算触顶则相反，沉默是明确语义；回复中途的限额自 2026-09-07 起改为止付收尾（goal 6、D12 修订）。（曾有的细化——事件召回失败降级为无记忆回复——随每轮推送一并删除，见 D14。）

**D7 兴趣向量层删除**：维护成本超过它省下的钱（同 v5）。

**D8 机制存在性三问**：它防的问题真的存在吗？有没有更简单的东西已覆盖？它会不会自己长出更多复杂度？

**D9 视觉单模型**（2026-08-27）：`vision-exp` 文本持平 V4-Flash 且同价，回复从 Pro 切来省约 3 倍，还免去双档路由。文本弱于 Pro 是接受的代价。

**D10 ~~全线禁思~~ → 深思分级**（2026-08-27，08-29 修订）：抽取一趟曾思考 6k token 而产出只值其十分之一——schema 与 Validator 已承担「想清楚」的职责。但全关后回复变笨，拥有者要求恢复：三条路径的思考各自配置分级（`reasoning_effort`: off/low/high/max，映射厂商同名参数，off 走各后端的免思考通道），当前均为 low。09-09 补充：反直觉规则（别名再确认为最）与思考共存亡——pro+off 连挂 3 次、flash+low 连挂 2 次（索引式检查清单也救不回），flash+high 全过（eval_extract 实测）；抽取由此获得独立的模型档，flash+high 组合实测省约六成，当晚裁定回退到 pro+low——旋钮保留，负面结果记档。09-09 后续：抽取的模型、思考档与超时合并为 `llm.text.extract` 一块（超时此前硬编码在 `memory_extractor` 里），三个设置一个来源。

**D11 ~~图片~~ 媒体到达即理解**（2026-08-27，09-07 扩至语音）：链接新鲜、每图只付一次（缓存）、不回复的群也有可读归档。语音随后跟进：归纳只读文本，回复时才付费让没人问过的语音永远进不了记忆，而语音比图片更少更便宜——「付费动作等回复」的纪律整体退役。

**D12 ~~超限即沉默~~ → 超限即止付**（2026-08-27，09-07 修订）：三种限额曾统一为沉默，半途已花的钱作废。拥有者裁定约束目标是消耗有界而非严格不超支：回复中途触顶改为一轮无工具收尾作答，已花的钱产出回复，超射有界（恰好一轮）；日预算拦在花钱之前，仍是沉默。

**D13 token 预算机制删除**（2026-08-27）：钱已是唯一限制，token 上限是伪装成布局的第二套预算。留下的窗口条数是上下文与缓存的需要，不是成本控制。

**D14 事件记忆改为只拉不推**（2026-09-07）：曾按轮推送【相关的事】——以本轮发言人与被 @ 者过滤参与者、向量排序后贴在当前消息上方。真实事故：一条 @ 到某成员的省略问句，把召回出的他的旧事当成了先行词，答非所问；推送块无日期无说明、又占据指代消解最敏感的位置，是结构性诱导。删除推送，往事只经 recall_events 工具按需拉取；顺带每条回复省一次 embedding 调用。不查就给的，只留每条回复都需要的东西。
